# Feature: TP2.0 — pre-UDS module access (experimental, CAN, the moonshot)

VW/VAG **Transport Protocol 2.0** carries KWP2000 to the modules that do **not** answer UDS/ISO-TP
on PQ-platform cars (cluster, comfort, gateway). It is what a VCDS **auto-scan** uses to reach the
whole car. This lifts the [module-scan](./module-scan.md) from "UDS modules only" toward a true
full-car scan: **gateway installation list + per-module ident + per-module faults** (VAG 5-digit
codes).

> ⚠️ **EXPERIMENTAL — the hardest thing here.** TP2.0 over a *generic* ELM327 needs raw-CAN mode
> and is timing-sensitive. The byte layer is pinned by a **golden-trace test** replaying the
> canonical published real-car exchange (not just self-consistency with the fake bus), and the
> stack implements block-size ACKs and keep-alives — but per-frame turnaround through an ELM327 is
> slow versus TP2.0's ~100ms ack window, so it works on some adapters and not others. A
> **capability probe** runs before every hardware scan to fail fast on clones that can't do raw
> CAN. Never offered on non-CAN links.

## Architecture (simulator-first, like the rest of the engine)
The protocol is pure and driven through a tiny `RawCanLink` (send one CAN frame / receive frames,
optional receive-filter hint), so it runs with no hardware:
- `tp20/tp20.ts` — framing (`toTpFrames` honoring block size, ACK/last-frame helpers) and
  `Tp20Channel`: `open` → channel setup (response accepted on 0x200 **and** 0x200+dest, id
  orientation per the canonical trace, invalid-id flag checked) + parameter handshake (peer block
  size captured), `request` → KWP round-trip with mid-packet ACKs both directions, NOT_READY (0x9)
  tolerance and peer-disconnect (0xA8) detection, `close`. Idle channels stay alive via 0xA3
  channel tests (answered with 0xA1 both ways). Bounded inbox, cleared per open — no stale-frame
  matching. Plus `parseGatewayInstallList` and `parseKwpDtcs` (KWP 0x58 → VAG 5-digit codes).
- `tp20/fakeTp20Bus.ts` — an in-memory gateway + pre-UDS modules answering channel setup (canonical
  byte order/ids), params, keep-alives and a small KWP layer (ident `1A`, session `10`, faults
  `18`, install list `21 0B`), **pausing at block boundaries** like a real module so the tester's
  mid-packet ACKs are actually exercised; `buildTp20BusFromProfile` wires it from the vehicle
  profile (incl. `tp20SampleDtcs`) so tests and the simulator exercise the exact scan the UI runs.
- `tp20/tp20Scan.ts` — `scanTp20`: open the gateway (addr 0x19), read its installation list, then
  per target module: session start (`10 89`, best-effort), ident (`1A 9B`), faults
  (`18 02 FF 00`). Results tagged `ok` / `refused` (channel opened, KWP 0x7F) / `silent` /
  `not-installed`; a gateway failure degrades to `gatewayError` + direct probing of the wanted
  modules instead of blanking the scan.
- `tp20/elmRawCan.ts` — `Elm327RawCanLink`, the real-hardware `RawCanLink`: ATCAF0/ATH1/**ATS1**
  raw-CAN + ATMA monitor; frames printed inside the send command window (where the module's
  immediate ACK lands) are parsed, not dropped; per-channel receive filters (ATCRA / ATCF+ATCM) so
  ATMA doesn't flood cheap clones; state restored (ATCAF1/ATH0/ATS0 + filter clear) on `end()` so
  normal OBD parsing survives a TP2.0 scan; STN/OBDLink adapters detected via `STI` get a
  one-command `STPX` send path. `probeTp20Capability` = the pre-scan raw-CAN sanity check.
  Device-only glue like `BleTransport`, but the pure parts (`parseRawCanLine`, command sequences)
  are unit-tested against a scripted client.
- `tp20/vagModules.ts` — VAG address → module-name table for labelling.

## Feature integration
`module-scan` gains a **"Scan gateway (TP2.0)"** action (shown only when the profile declares
`transport: 'tp20'` modules and the link is CAN). On the simulator (mock adapter) it runs against
`buildTp20BusFromProfile`; on hardware it probes raw-CAN capability first, then uses
`Elm327RawCanLink` over the live session. The result shows the gateway's full install list (named
via `vagModuleName`), each pre-UDS module's ident and stored faults (VAG 5-digit codes + status
byte), per-module `refused`/`silent` distinction, and a visible error row (probe failed, gateway
unreachable) instead of a silent log. The Golf profile ships a gateway install list plus
cluster/comfort/gateway TP2.0 modules with sample idents and comfort-system sample faults.

## Acceptance
- Core: `tp20.test.ts` — framing (block boundaries, rolling seq), install-list decode, KWP fault
  parse, multi-frame reassembly, **mid-packet ACKs in both directions (blockSize 2)**, keep-alive
  (0xA3 counted, channel survives idle, stops on close), channel timeout for absent modules.
- Golden trace: `tp20GoldenTrace.test.ts` — byte-for-byte replay of the canonical real-car
  exchange (setup on 0x201, params on 0x740/0x300, ident, ACK seq, disconnect), plus negative
  setup response and invalid-id flag rejection. This is what pins real-ECU byte compatibility
  without a car.
- Scan: `tp20Scan.test.ts` — profile-driven scan (cluster + comfort identified, unfitted address
  `not-installed`), per-module faults (seeded comfort codes 00928/01330, clean cluster `[]`),
  gateway-failure degradation, `refused` vs `silent`.
- Hardware glue: `elmRawCan.test.ts` — line parser (incl. the ATS0-glue failure mode), begin/end
  command sequences, command-window frame capture, filters, STPX path, capability probe.
- UI: on the Golf simulator, "Scan gateway (TP2.0)" lists the installed modules by name, idents,
  and comfort faults; hidden entirely for the K-line Passat and the non-VAG Punto.

## Honest limits
- **Passat B5.5** is still out: its modules are KWP1281, a different (pre-TP2.0) link an ELM327
  cannot do — see [service-reset](./service-reset.md).
- The golden trace pins the byte layer, but **real-car reliability still depends on the adapter**
  (per-frame monitor stop/start ≈200ms vs the module's ~100ms ack window T1). STN/OBDLink chips
  are the realistic path to reliable TP2.0; treat every generic-clone TP2.0 read as unverified
  until confirmed on a car.
- The gateway install-list bitmap semantics (`21 0B` → bit n of byte b = address b*8+n) are
  plausible-but-unverified on a real gateway.
- Fault reads are KWP `18 02 FF 00` read-only; clearing (`14`) over TP2.0 is deliberately not
  wired yet — writes stay in the guarded coding paths.
