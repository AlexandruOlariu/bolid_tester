# Plan 29 — Adapter compatibility matrix

**Size:** M (1 day) · **Depends on:** plan 12 (`linkStore` for MTU/service details; optional) ·
**Roadmap:** v0.7 "Adapter compatibility matrix"

## Goal

Every adapter-health run can be shared as a **structured JSON report**; reports contributed to the
repo are turned by a script into a committed matrix (`docs/adapters/matrix.md`) and per-adapter
pages, and the same data is bundled into the app as a **Known adapters** list that labels scanned
devices and health results ("3 community reports · typically GOOD"). The pipeline is complete and
tested with zero reports; real reports arrive later.

## Why

`src/features/adapter-health` grades an adapter and shares plain text. The knowledge dies in a chat
thread. A matrix answers "will my adapter work?" before anyone buys one, and the in-app list turns
the grade into context.

## Design

### Report JSON (schema v1) — `src/features/adapter-health/api/adapterReportJson.ts` (pure)

```ts
export interface AdapterReportJson {
  schema: 1;
  app: { version: string; platform: 'android' | 'ios' | 'web'; os?: string };
  adapter: {
    deviceName: string | null; // BLE advertised name, e.g. "IOS-Vlink"
    firmware: string; // ATI
    link: 'ble' | 'wifi' | 'spp' | 'web-ble' | 'mock';
    service?: string;
    writeWithoutResponse?: boolean;
    mtu?: number; // from linkStore when present
  };
  vehicle: { profileId: string; protocol: string };
  measurements: {
    voltage: number | null;
    latenciesMs: number[];
    attempts: number;
    latency: AdapterLatencyStats | null;
  };
  grade: { grade: AdapterGrade; cloneSuspected: boolean; notes: string[] };
  ranAt: string; // ISO
}
export function buildAdapterReportJson(
  report: AdapterHealthReport,
  ctx: {
    appVersion: string;
    platform: AdapterReportJson['app']['platform'];
    os?: string;
    deviceName: string | null;
    link: AdapterReportJson['adapter']['link'];
    profileId: string;
    linkInfo?: { service: string; writeWithoutResponse: boolean; mtu: number } | null;
  },
): AdapterReportJson;
/** Stable file/page slug: normalised device name + firmware, e.g. "ios-vlink__elm327-v2-2". */
export function adapterSlug(deviceName: string | null, firmware: string): string;
```

`useAdapterHealth.share()` gains a `format: 'txt' | 'json'` argument; the screen shows **Share as
text** and **Share JSON (for the compatibility matrix)**. Platform/version via `expo-constants`
(`Constants.expoConfig?.version ?? '0.0.0'`) and `Platform.OS`; `deviceName` from
`useSessionStore.getState().deviceName`; `link` from `linkStore.kind` (plan 12) else `'ble'`
(`'mock'` when `adapterSource === 'mock'` — such reports are refused by the build script).

### Repository data

```
docs/adapters/
├── README.md              # how to contribute a report; what the grades mean
├── reports/               # one AdapterReportJson per run: <slug>__<yyyy-mm-dd>.json
├── matrix.md              # GENERATED — do not edit
└── <slug>.md              # GENERATED per adapter
```

`scripts/build-adapter-matrix.mjs` (node ≥ 20, no deps):

- Reads `docs/adapters/reports/*.json`, validates `schema === 1`, rejects `adapter.link === 'mock'`
  and malformed files with a non-zero exit and a clear message.
- Groups by `adapterSlug`; per group computes report count, grade distribution, median of medians,
  protocols seen, platforms seen, clone-suspected ratio, last report date.
- Writes `matrix.md` (table: Adapter · Firmware · Link · Reports · Typical grade · Median ms ·
  Protocols · Platforms · Page) sorted by typical grade then name, with a header line "Generated by
  `scripts/build-adapter-matrix.mjs` from N reports on <date>"; with zero reports writes the table
  header and "No reports yet — see README.md".
- Writes one page per adapter with the per-report rows and every note.
- Writes `src/shared/adapters/knownAdapters.json`: `[{ slug, nameHints: string[], firmware, link,
reports, typicalGrade, medianMs, cloneSuspectedRatio }]` (compact; no notes).
- `--check` mode regenerates into memory and exits 1 if any output differs from the committed file
  (so CI enforces regeneration). Add `"adapters:build": "node scripts/build-adapter-matrix.mjs"`
  and `"adapters:check": "node scripts/build-adapter-matrix.mjs --check"` to `package.json`; add the
  check to the `verify` job after lint.

Hand-written adapter docs link in via an `EXTRA_DOCS` map in the script (`'ios-vlink' →
'../adapter-vgate-icar-pro.md'`), rendered as an extra column.

### In-app known adapters — `src/shared/adapters/`

```ts
export interface KnownAdapter {
  slug: string;
  nameHints: string[];
  firmware: string;
  link: string;
  reports: number;
  typicalGrade: AdapterGrade;
  medianMs: number | null;
  cloneSuspectedRatio: number;
}
export const KNOWN_ADAPTERS: KnownAdapter[]; // import knownAdapters.json
export function matchKnownAdapter(
  deviceName: string | null,
  firmware?: string | null,
): KnownAdapter | null; // name hint match first, firmware tie-break
export function communitySummary(k: KnownAdapter): string; // "3 reports · typically GOOD · ~28 ms"
```

- `DeviceRow.tsx`: when `matchKnownAdapter(device.name)` hits, show a small chip with
  `typicalGrade` ("known good" / "known ok" / "known poor").
- `AdapterHealthScreen.tsx`: under the grade, a `Paragraph theme="alt2"` with `communitySummary`
  when matched, else "No community reports for this adapter yet — share the JSON to add one."
- `tsconfig.json` core `include` does not cover `src/shared/adapters`; keep the pure module's test
  under `src/shared/lib/` (`knownAdapters.test.ts` importing from `@/shared/adapters`) or extend the
  include list — the test must run in the `core` jest project.

## Simulator

The simulator produces a valid report (`ELM327 v2.2`, `12.3V`, CAN, sub-5 ms latencies) with `link:
'mock'`; the share works end to end, and the build script's refusal of `mock` reports is covered by
a fixture test (`scripts/__tests__` is outside the jest roots — test the script by spawning it with
`child_process.execFileSync('node', ['scripts/build-adapter-matrix.mjs', '--check', '--reports',
'<tmp dir>'])` from a core test, supporting a `--reports <dir>` and `--out <dir>` override for
exactly this purpose).

## Tests

- `adapterReportJson.test.ts`: shape, ISO date, slug normalisation (`"IOS-Vlink"`, `"ELM327 v2.2"`
  → `ios-vlink__elm327-v2-2`; null name → `unknown__…`).
- `buildAdapterMatrix.test.ts` (spawns the script against a temp dir): zero reports → header + "No
  reports yet"; two reports for one slug + one for another → two rows, counts and median of medians
  correct, per-adapter pages exist, `knownAdapters.json` has two entries; a `mock` report → exit 1;
  `--check` with a stale output → exit 1.
- `knownAdapters.test.ts`: `matchKnownAdapter('IOS-Vlink')` with a seeded fixture list; no match →
  null; `communitySummary` text.
- `gradeAdapter.test.ts` unchanged.
