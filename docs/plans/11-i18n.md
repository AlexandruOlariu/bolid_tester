# Plan 11 — Localization: English and Romanian

**Size:** M–L (1½–2 days; string extraction is the bulk) · **Depends on:** plan 07 (strings settle
after the IA pass) · **Roadmap:** v0.5 "Localization"

## Goal

Every user-visible string goes through `i18next`; the app ships English and Romanian, follows the
device language by default, and lets the user override it in Settings. Numbers and dates format per locale; units stay metric.

## Why

The app is English-only; its first users are Romanian ("ITP" appears in the specs). Doing this after
the IA pass avoids translating strings that are about to move.

## Read first

- `src/app/_layout.tsx` (tab titles), the seven tab screens, then every `src/features/*/ui/*.tsx`.
- `src/shared/ui/{Gauge,ValueCard,StatusBadge}.tsx` (unit symbols are metric and are not translated).
- `src/shared/state/settingsStore.ts` (add `language`), `docs/features/settings.md`.
- `src/shared/obd-core/obd/pids.ts` PID names and `dtcDatabase` descriptions — **core strings stay
  English** (they are technical identifiers shown as-is; translating 2 000 DTC texts is a later data
  effort). Document this boundary.

## Design

### Dependencies and setup

`i18next`, `react-i18next`, `expo-localization` (native; `npx expo install expo-localization`).

```
src/shared/i18n/
├── index.ts            # init + helpers
├── locales/en/{common,connection,vehicle,live,faults,info,settings,more,...}.json
└── locales/ro/…        # mirror
```

`index.ts`:

```ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
export const SUPPORTED = ['en', 'ro'] as const;
export type Lang = (typeof SUPPORTED)[number];
export function resolveLanguage(pref: 'system' | Lang, deviceTags: string[]): Lang; // pure: first supported tag, else 'en'
export async function initI18n(pref: 'system' | Lang): Promise<void>; // loads expo-localization via tolerant import for the device tags
export function setLanguage(l: Lang): Promise<void>; // i18n.changeLanguage
```

Resources are statically imported JSON (RN bundles them). `interpolation.escapeValue = false`;
`compatibilityJSON: 'v4'`; `fallbackLng: 'en'`; `ns` = the file names; default ns `common`.

Mount: in `_layout.tsx` call `initI18n(pref)` once (`useEffect` + a `ready` flag that keeps
`AppSplash` up until resolved, so no English flash).

### Settings

`settingsStore`: `language: 'system' | 'en' | 'ro'` (default `'system'`), `setLanguage`, persist
version bump with `migrateSettings` default. Settings → General → **Language**: System / English /
Română. Changing it calls `setLanguage(resolveLanguage(pref, deviceTags))`.

### Extraction rules

- Keys are semantic, nested by screen: `connection.scan`, `connection.status.connected`,
  `faults.section.stored`, `settings.general.units`. No English-sentence keys.
- Use `t('key', { count })` with `_one`/`_other` for plurals; `{{value}}` interpolation; never
  concatenate translated fragments.
- Units are metric only; their symbols (km/h, °C, kPa, L/100km) are never translated. Numbers via
  `new Intl.NumberFormat(i18n.language)` in a `formatNumber(value, maxFractionDigits)` helper in
  `src/shared/lib/format.ts`; dates via `Intl.DateTimeFormat(i18n.language, …)` in `formatDate`
  (history, maintenance, trips, scan history).
- Technical identifiers that stay untranslated: PID names from the registry, DTC codes and
  descriptions, protocol labels (`PROTOCOL_LABELS`), module part numbers, AT commands, VAG code
  numbers. Romanian UI copy may add a translated gloss in parentheses where helpful.
- Accessibility labels are translated too (`accessibilityLabel={t('…')}`).

### Order of extraction

1. `_layout.tsx` tab titles and hidden-route titles.
2. Connect, Vehicle, Live, Faults, Info, Settings, More (the tabs).
3. Hidden routes by usage: History, Inspection, Battery, Maintenance, Trips, Charts, Alerts,
   Notifications, Adapter health, VIN decoder, DPF, Error log.
4. Workshop screens (module scan, adaptations, routines, coding, service reset, sniffer) — their
   safety copy must be translated carefully; keep the English next to it in `ro.json` comments is
   not possible in JSON, so review these in the PR explicitly.
5. Shared UI (`StatusBadge` states, `Gauge` a11y labels), `EngineHost` notification titles/bodies
   (`notify({ title, body })` — pass translated strings; the notifier is UI-agnostic).

## Tests

- `src/shared/i18n/i18n.test.ts` (core tsconfig excludes `src/shared/i18n` — add it to
  `tsconfig.json` `include`, or place the pure parts under `src/shared/lib/i18nResolve.ts`):
  - `resolveLanguage('system', ['ro-RO'])` → `ro`; `['de-DE']` → `en`; explicit pref wins;
  - **parity**: every key path in `en/*.json` exists in `ro/*.json` and vice versa; no empty values;
    interpolation placeholders (`{{…}}`) identical per key; plural suffix sets match.
- Plan 10 UI tests: render `SettingsScreen` with `ro` → the Theme label reads `Temă`.
