# Plan 08 — Signed release build, versioning, OTA updates

**Size:** S–M (½–1 day + owner secrets) · **Depends on:** nothing · **Roadmap:** v0.2 "Signed
release build"

## Goal

CI produces a **release-signed** APK and AAB with a real version code, GitHub Releases are cut from
`v*` tags instead of every push, EAS Update is configured so JS-only fixes ship over the air, and a
privacy policy exists because the app now talks to an update server.

## Why

`.github/workflows/ci.yml` signs with the debug keystore and tags every push to `main` as
`v0.1.0-buildN`; `app.json` has `TODO-eas-project-id`; version `0.1.0` has not moved in 37 builds.
Nothing from this pipeline can go to a store or be updated in place.

- `.github/workflows/ci.yml` (both jobs), `app.json`, `eas.json`, `package.json` scripts,
  `src/features/more/api/updates.ts`, `.claude/skills/android-apk/SKILL.md`.

## Design

### Owner prerequisites (collect first)

1. Generate the upload keystore **locally, once**, and store it in a password manager:
   ```powershell
   keytool -genkeypair -v -keystore bolid-release.keystore -alias bolid -keyalg RSA -keysize 2048 -validity 10000
   ```
2. GitHub → Settings → Secrets → Actions: `ANDROID_KEYSTORE_B64` (`base64 -w0 bolid-release.keystore`
   or `[Convert]::ToBase64String([IO.File]::ReadAllBytes('bolid-release.keystore'))`),
   `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`bolid`), `ANDROID_KEY_PASSWORD`.
3. Expo account: `npx eas-cli login`, then `eas init` in the repo (writes `extra.eas.projectId`),
   then `eas update:configure` (writes `updates.url`). Add `EXPO_TOKEN` secret for CI publishing.

Never commit the keystore or `.jks`/`.keystore` files — add `*.keystore` and `*.jks` to `.gitignore`.

### Config plugin `plugins/withReleaseSigning.js`

`android/` is gitignored and regenerated by `expo prebuild`, so signing must be injected at prebuild
time. Register in `app.json` `plugins: [..., "./plugins/withReleaseSigning"]`.

```js
const { withAppBuildGradle } = require('expo/config-plugins');

/** Adds a `release` signingConfig driven by env vars and applies it to the release build type.
 *  When BOLID_KEYSTORE_PATH is unset (local dev) the debug key stays, so `npm run android:apk` keeps working. */
module.exports = function withReleaseSigning(config) {
  return withAppBuildGradle(config, (c) => {
    let g = c.modResults.contents;
    if (!g.includes('signingConfigs.release')) {
      g = g.replace(
        /signingConfigs \{/,
        `signingConfigs {
        release {
            def ksPath = System.getenv("BOLID_KEYSTORE_PATH")
            if (ksPath) {
                storeFile file(ksPath)
                storePassword System.getenv("BOLID_KEYSTORE_PASSWORD")
                keyAlias System.getenv("BOLID_KEY_ALIAS")
                keyPassword System.getenv("BOLID_KEY_PASSWORD")
            }
        }`,
      );
      g = g.replace(
        /release \{\s*\n(\s*)signingConfig signingConfigs\.debug/,
        (m, indent) =>
          `release {\n${indent}signingConfig System.getenv("BOLID_KEYSTORE_PATH") ? signingConfigs.release : signingConfigs.debug`,
      );
    }
    const vc = process.env.BOLID_VERSION_CODE;
    if (vc) g = g.replace(/versionCode \d+/, `versionCode ${vc}`);
    c.modResults.contents = g;
    return c;
  });
};
```

Verify the regexes against the generated `android/app/build.gradle` of this Expo SDK (run `npx expo
prebuild --platform android --no-install` locally and inspect) — adjust if the template differs.
Add a Jest test under `plugins/__tests__/withReleaseSigning.test.js`? The core tsconfig excludes it;
instead add a tiny node script `scripts/check-signing-plugin.mjs` that applies the plugin to a
fixture gradle string and asserts the three replacements; run it in the `verify` CI job.

### CI changes (`.github/workflows/ci.yml`)

- `verify` job: unchanged + `node scripts/check-signing-plugin.mjs`.
- `build-android` (rename of `release-android`), runs on every push to `main` **and** on tags
  `v*`:
  ```yaml
  - name: Restore keystore
    if: ${{ secrets.ANDROID_KEYSTORE_B64 != '' }}
    run: echo "$ANDROID_KEYSTORE_B64" | base64 -d > "$RUNNER_TEMP/release.keystore"
    env: { ANDROID_KEYSTORE_B64: ${{ secrets.ANDROID_KEYSTORE_B64 }} }
  - name: Generate native Android project
    run: npx expo prebuild --platform android --no-install
    env:
      BOLID_KEYSTORE_PATH: ${{ runner.temp }}/release.keystore
      BOLID_VERSION_CODE: ${{ github.run_number }}
  - name: Build
    working-directory: android
    run: ./gradlew assembleRelease bundleRelease --no-daemon
    env:
      BOLID_KEYSTORE_PATH: ${{ runner.temp }}/release.keystore
      BOLID_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
      BOLID_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
      BOLID_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
  - name: Verify signature
    run: $ANDROID_HOME/build-tools/*/apksigner verify --print-certs android/app/build/outputs/apk/release/*.apk | tee sig.txt && ! grep -q "Android Debug" sig.txt
  ```
  Upload `bolid-tester-v<version>-<run>.apk` and `.aab` as artifacts on every main push. Create the
  GitHub Release **only** when `startsWith(github.ref, 'refs/tags/v')`, titled from the tag, with
  both files and auto-generated notes (`gh release create "$TAG" … --generate-notes`).
- Fail the build (not silently debug-sign) when the tag build runs without the keystore secret.

### Versioning convention

- `package.json` `version` and `app.json` `expo.version` are the single source (keep equal; add a
  `scripts/check-version-sync.mjs` run in `verify`).
- Release = `npm version minor|patch` (creates the commit + `vX.Y.Z` tag) → `git push --follow-tags`.
  Document in `docs/release.md` (new): steps, what CI does, where artifacts land, how to roll back
  (re-tag previous).
- `versionCode` = CI run number (monotonic across all builds; Play requires strictly increasing).

### OTA (EAS Update)

- `eas.json`: add `"channel": "preview"` to the `preview` profile and `"channel": "production"` to
  `production`. `runtimeVersion.policy = appVersion` (already) → an OTA only reaches builds with the
  same `expo.version`; any native dependency change requires a new version + APK.
- CI job `ota-publish` on `v*` tags after `build-android`: `npx eas-cli update --branch production
--message "$TAG" --non-interactive` with `EXPO_TOKEN`. Manual hotfix: `eas update --branch
production --message "fix: …"` from a dev machine on the release branch.
- `More → Check for updates` already handles `unavailable`; after configuration, verify it returns
  `up-to-date` on a release build.

### Privacy policy

`docs/privacy-policy.md` (and later a hosted copy for the stores): data stays on device; network
calls only to (1) the OpenAI-compatible server the user configures, (2) the Expo update server
when the user taps Check for updates or at launch (`checkAutomatically` — set
`"checkAutomatically": "ON_ERROR_RECOVERY"` in `app.json` `updates` so the app never checks
silently on launch); no analytics, no accounts; Bluetooth and location permissions and why; how to
delete data (Settings → Reset all app data, plan 07). Link it from Settings → About.

## Steps

1. `.gitignore` keystore patterns; `plugins/withReleaseSigning.js`; `scripts/check-signing-plugin.mjs`;
   `scripts/check-version-sync.mjs`; register plugin in `app.json`.
2. `ci.yml` as designed; `eas.json` channels; `app.json` `updates.checkAutomatically`.
3. Owner: keystore + secrets + `eas init` + `eas update:configure` (commit the resulting `app.json`).
4. `docs/release.md`, `docs/privacy-policy.md`; root README "Releases" section.
5. Bump to `0.2.0` when the v0.2 items are in; tag; watch CI; verify the signature and OTA.

## Acceptance

- [ ] Tag build artifact: `apksigner verify --print-certs` shows the upload cert (not "Android
      Debug"); `aapt dump badging` shows `versionCode` = run number and `versionName` = tag.
- [ ] Push to `main` without a tag uploads artifacts but creates no Release.
- [ ] Tag build without the keystore secret fails loudly.
- [ ] `More → Check for updates` on the signed build reports up-to-date; a test `eas update` on the
      `preview` branch is picked up by a preview build.
- [ ] `docs/release.md` and `docs/privacy-policy.md` exist; About links the policy.
