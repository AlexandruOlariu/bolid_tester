## Engineering audit

### Strengths

- **Layered, pure core.** The engine has no RN dependency and runs the same `DiagnosticSession` in
  tests, the simulator and on BLE. The simulator reproduces real-adapter quirks (ISO-TP multi-frame
  printout, bare-`ATSH` rejection, stale `ATCRA`, multi-ECU lines, NRC `0x78`), so regressions in
  parsing are caught without a car.
- **Safety model for writes is coherent.** Backup → write → verify, `resetAddressing()` in every
  `finally`, interlocks that fail closed and re-check during a run, safety modules excluded, every
  illustrative byte badged as such in the UI.
- **Data lifecycle is sound.** Ring-buffered I/O log, capped persisted stores, file-backed persistence,
  API key in the OS keystore, root error boundary, single poll loop.
- **Docs-first with enforcement.** 28 feature specs, 3 vehicle docs kept in sync by a test, an
  implementation log, and a queryable context graph.
- **CI gate + release pipeline.** Lint, typecheck (core + app) and tests on every push; an installable
  APK on every push to `main`.

### Gaps, ranked by impact

1. **No recorded on-car validation.** `testing.md` asks for observed results per car; none exist.
   Tier B/C features (25 slices) are simulator-proven only, and every Tier C address, DID and routine
   id is a placeholder. Risk: the product is an excellent simulator of a diagnostics app.
2. **Developer defaults ship to users.** A fresh install starts in simulator mode, emulating the Golf
   with an injected `P0299`. A new user "connects" to a fake car and sees a fake fault.
3. **DTC knowledge is tiny.** 21 generic + 14 VAG descriptions versus thousands of SAE J2012 codes.
   For a generic diagnostics app this is the most visible functional gap.
4. **Vehicles are code, not data the user can create.** Adding a car means a TS profile, a Markdown doc
   and a sync test. There is no garage, no "learn this car" from a live connection, no custom profile.
5. **Information architecture.** More is a flat list of 22 entries mixing daily tools with gated
   writes; Settings mixes simulator/dev controls with user preferences; `sensor-readings` duplicates
   Live. No search. A dead imperial unit path (store field + conversion library) was never exposed in Settings; decision 2026-11-08: metric only, delete it (plan 07).
6. **Release engineering.** Debug keystore, version `0.1.0` across 37 builds, EAS placeholder, no iOS
   build, no privacy policy, OTA updates not enabled.
7. **Test pyramid stops at pure logic.** `testMatch` is `**/*.test.ts` in a node environment: 0 component
   tests, 0 end-to-end. UI regressions are caught only by `tsc`.
8. **Docs drift.** 5 slices without a spec (`can-sniffer`, `sensor-readings`, `onboarding`,
   `engine-host`, `more`); `phase2-mobile-app.md` maps 7 features; the root README feature table omits
   Tier C; `docs/README.md` doesn't index the roadmap docs.
9. **Accessibility and language.** 7 `accessibilityLabel` usages in the whole app; English only.
10. **One adapter family.** BLE only. Wi-Fi ELM327 and classic-SPP adapters (most cheap Android
    adapters) cannot connect; the Web Bluetooth transport stays deferred.
11. **Minor:** performance tests integrate 1 Hz integer OBD speed without GPS fusion; AI needs a
    self-hosted server; the untracked Codex mirror duplicates the context graph.

## What to do next

Three iterations, each independently shippable. Sizes: S ≤ ½ day, M ≈ 1 day, L ≈ 2–3 days (L\* needs
the car).

### Iteration 1 — make the next on-car session count

1. **Production defaults + first-run (S).** [Plan 01.](./plans/01-production-first-run.md) Default `adapterSource` to BLE on first launch; make the
   simulator an explicit opt-in with a persistent banner; drop the injected `P0299` default; a
   three-step first-run card (pick car → connect → read faults).
2. **On-car validation campaign, Golf first (L\*).** [Plan 02.](./plans/02-on-car-validation.md) Run the `testing.md` checklist for Connect / Live /
   Faults / Info / Inspection / Battery; capture the adapter I/O log for each flow and convert it to
   replay fixtures (`logReplay`); record observed protocol, PID bitmap and VIN in
   `docs/vehicles/golf-plus-2009-20tdi.md`; fix what breaks. Then the Punto, then the Passat.
3. **Sniffer "save capture" (S).** [Plan 03.](./plans/03-sniffer-capture.md) Persist and share an `ATMA` capture, so a VCDS Group 121 session can
   be recorded and the real routine bytes recovered. This is the unlock for Tier C.
4. **Doc debt (S).** [Plan 04.](./plans/04-doc-debt.md) Specs for the 5 undocumented slices; refresh the root README and
   `phase2-mobile-app.md`; index the roadmap docs.

### Iteration 2 — any car, any code

5. **DTC database (M).** [Plan 05.](./plans/05-dtc-database.md) Full SAE generic set (P0xxx / P2xxx / P3xxx / B0 / C0 / U0) as a compact
   data module with description, system and a severity hint; a DTC detail sheet (meaning, typical
   causes, linked guide / freeze frame / AI explain).
6. **Garage + learned profiles (L).** [Plan 06.](./plans/06-garage-learned-profiles.md) Multiple saved cars; create a profile in-app from a live connection
   (VIN, protocol, supported-PID bitmap, Mode 09 calibration IDs) and persist it; per-car history,
   maintenance and dashboard layout already key by vehicle.
7. **More / Settings IA (M).** [Plan 07.](./plans/07-information-architecture.md) Group More into Diagnose · Drive · Ownership · Workshop (experimental) ·
   Tools; split dev/simulator controls into a "Developer" section; fold `sensor-readings` into Live as
   a grouped view.

### Iteration 3 — ship like a product

8. **Signed release + versioning (S).** [Plan 08.](./plans/08-signed-release-ota.md) Release keystore via CI secret, semantic version bump, EAS
   project id, OTA enabled.
9. **iOS via EAS (M).** [Plan 09.](./plans/09-ios-eas.md) First TestFlight build; verify BLE discovery on iOS.
10. **Component test harness (M).** [Plan 10.](./plans/10-component-e2e-tests.md) `jest-expo` + React Native Testing Library for the 7 tab screens;
    one Maestro smoke flow (simulator connect → read faults → clear).
11. **i18n scaffold (M).** [Plan 11.](./plans/11-i18n.md) `i18next` with English + Romanian; extract strings from the 7 tabs first.

Each numbered item above has a handoff-grade plan in [`plans/`](./plans/README.md). The full feature plan these iterations feed into is in [`roadmap.md`](./roadmap.md).
