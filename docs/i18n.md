# Localization (i18n)

The app ships in **English** and **Romanian** ([plan 11](./plans/11-i18n.md)). It follows the
phone's language by default; **Settings → General → Language** overrides it (**Phone language** /
**English** / **Română**) and switches live, without a restart. Numbers and dates follow the
language; units stay metric and their symbols are never translated.

The Romanian copy is a **draft for the owner's review** (see [Owner review](#owner-review)).

## Setup

| Piece                                    | What it does                                                                                                                                                                                                                                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `i18next`, `react-i18next`               | Translation runtime. Resources are bundled JSON, so i18next initialises **synchronously in English** at import (`initAsync: false`): the first render and every test have strings.                                                                                                           |
| `expo-localization`                      | The device's preferred locales (`getLocales()`), loaded with a variable import specifier like the other optional native modules; absent (tests, web without it) → `[]` → English.                                                                                                            |
| `intl-pluralrules`                       | `Intl.PluralRules` polyfill. Hermes has none; i18next needs it for `_one` / `_few` / `_other`. It installs itself only when the runtime lacks it.                                                                                                                                            |
| `src/shared/i18n/index.ts`               | Init, `initI18n(pref)`, `setLanguage(lang)`, `currentLanguage()`, `translate(key, values)` (for code outside React) and the re-exported `useTranslation` / `Trans`. Import these from `@/shared/i18n`, never from `react-i18next`: importing the module is what initialises i18next.         |
| `src/shared/i18n/useLanguageSync.ts`     | Root-layout hook: waits for the settings file to hydrate, resolves the stored preference, applies it and re-applies on every change. The splash (`AppSplash ready={…}`) stays up, and shows no words, until the first language is applied, so a Romanian phone never shows an English frame. |
| `src/shared/i18n/locales/{en,ro}/*.json` | One file per namespace and language. `locales/index.ts` imports them statically (Metro bundles them) and lists `NAMESPACES`.                                                                                                                                                                 |
| `src/shared/lib/i18nResolve.ts`          | Pure: `SUPPORTED`, `resolveLanguage(pref, deviceTags)` (explicit preference wins; `system` → first supported device tag, else English), `isLanguagePref`.                                                                                                                                    |
| `src/shared/lib/format.ts`               | Pure: `formatNumber(value, maxFractionDigits, options)`, `formatFixed` (a locale `toFixed`), `formatDate`, `formatDateTime`, `formatTime`. The i18n module calls `setFormatLocale` on every language change. `12.5` in English, `12,5` in Romanian.                                          |
| `src/shared/lib/i18nParity.ts`           | Pure completeness check used by the parity test.                                                                                                                                                                                                                                             |

The preference is `settingsStore.language: 'system' | 'en' | 'ro'` (default `'system'`, settings
schema v9; an older file migrates to `'system'`, an unknown stored value is ignored).

## Namespaces and key conventions

- `common` — tab and route titles (`nav.*`), shared actions (`actions.ok|cancel|close|done|…`),
  connection states, shared components (status badge, gauge, value card, verification / unlock
  badges, import preview, error boundary), fuel names and share-sheet titles (`share.*`).
- One namespace per feature slice: the camelCase of its folder — `connection`, `vehicleSelect`,
  `liveData`, `faultCodes`, `vehicleInfo`, `settings`, `more`, `history`, `inspection`,
  `batteryHealth`, `maintenance`, `tripRecording`, `liveCharts`, `alerts`, `notifications`,
  `adapterHealth`, `vinDecode`, `dpf`, `errorLog`, `moduleScan`, `adaptations`, `routines`, `coding`,
  `serviceReset`, `canSniffer`, `aiDiagnose`, `backup`, `extendedPids`, `feedback`, `onboarding`,
  `performanceTests`, `report`, `sensorTests`, `engineHost`.
- Keys are **semantic and nested by screen part** (`connection.ble.scan`,
  `faultCodes.section.stored`, `settings.general.theme`), never English sentences.
- Plurals: `t('key', { count })` with `key_one` / `key_other` in English and `key_one` / `key_few` /
  `key_other` in Romanian (the categories `Intl.PluralRules` reports). Never build a plural with
  `n === 1 ? '' : 's'`.
- Values: `{{name}}` interpolation; never concatenate translated fragments. Rich text (a bold word in
  a sentence) uses `<Trans i18nKey="ns:key" components={{ b: <Text fontWeight="700" /> }} />` with
  `<b>…</b>` in the string.
- Accessibility labels and hints are translated like visible text.
- Code outside React (services, hooks' status messages, model helpers, notifications) calls
  `translate('ns:key', values)`. A message stored for later (e.g. the adapter-source fallback notice)
  is stored **as a key** and translated when shown.
- Numbers shown to the user go through `formatNumber` / `formatFixed`; dates through `formatDate` /
  `formatDateTime` / `formatTime` — never `toFixed` / `toLocaleString` in UI code.

## What stays English (the untranslated-identifier boundary)

- **Technical identifiers:** PID names from the registry, DTC codes and their descriptions (the SAE
  J2012 / VAG database — translating ~2 000 texts is a later data effort), protocol labels
  (`PROTOCOL_LABELS`), module part numbers, AT commands, VAG code numbers, DIDs, NRC codes, unit
  symbols (km/h, °C, kPa, L/100km, V, ms).
- **Core and shared-library output** (`src/shared/obd-core`, `src/shared/lib`, `src/shared/vehicles`,
  `src/shared/adapters`): analysis texts (inspection checks, battery notes, adapter grade notes,
  drive-cycle patterns, GPS-vs-OBD notes, report headlines), backup / import validation messages and
  transport error messages. These modules are typechecked without React and stay i18n-free; their
  English is shown as-is. One exception: the starter alert rules' names (`defaultRules`) are shown
  from `alerts:defaultRule.<id>` while the user has not renamed them (`ruleLabel`,
  `src/features/alerts/model/ruleLabel.ts`).
- **Documents and files that leave the phone:** the vehicle / fault-code / auto-scan reports (PDF,
  HTML, Markdown, text), CSV exports, the feedback bundle, the connection-diagnostics "Copy details"
  frame, the adapter-health report. They are shared with mechanics, forums and the maintainer, so
  their structure stays English (the diagnosis text inside the diagnostics report follows the UI).
- **Data:** vehicle-profile names and notes, curated fault-guide notes, coding presets, label packs,
  routine descriptions, AI answers (the model answers in whatever language it chooses).
- **The privacy policy** (Settings → About) is published in English (`docs/privacy-policy.md`); in
  Romanian the screen says so. A Romanian legal text needs a separate review.
- **Brand and product names** (Bolid Tester, VCDS, ELM327, OBD2, Wi-Fi, Bluetooth LE, Claude,
  ChatGPT).

### The AI diagnostic agent (plans 34a-34d)

The agent has a **model-facing** side and a **user-facing** side; only the second is translated.

- **Stays English (model-facing, or leaves the phone):** the capability skill documents
  (`*.skill.json`) and playbooks, tool descriptions and argument schemas, every tool's digest and
  summary, the driver instructions' `en` text, the prompts, and the **Send to Claude / ChatGPT**
  share package (a document that leaves the phone). The model's own report text is the model's
  language.
- **Translated (en + ro):** each tool's label (`labelKey`, e.g. `aiDiagnose:agent.tool.read_live`,
  `faultCodes:agent.tool.*` in the contributing feature's namespace), the trail's step labels
  (`aiDiagnose:agent.step.*`, `agent.invalid`), the driver instructions
  (`aiDiagnose:agent.driver.<id>`) and their answer choices (`aiDiagnose:agent.driverChoice.<value>`),
  the driver prompt (`agent.driverPrompt.*`), the end-of-run notices (`aiDiagnose:agent.end.<end>`),
  and every on-device finding's title and detail (`aiDiagnose:agent.finding.<area>.<id>.title` /
  `.detail`; feature findings under `<featureNs>:agent.finding.*`).
- A new tool, driver instruction, choice, end reason or core finding adds its en + ro keys in the
  same change; `src/features/ai-diagnose/agentStrings.test.ts` fails otherwise.

Romanian copy may add a translated gloss in parentheses where it helps, e.g. "monitoare readiness
(pregătire ITP)", "freeze frame (instantaneu la eroare)".

## Tests

- `src/shared/lib/i18nParity.test.ts` — every JSON file on disk is registered in
  `locales/index.ts`; every English key exists in Romanian and vice versa; no empty value;
  `{{placeholders}}` identical per key; plural keys carry each language's categories; no cedilla
  diacritics. **Removing a key from one language fails CI.**
- `src/shared/lib/i18nResolve.test.ts`, `src/shared/lib/format.test.ts` — language resolution and
  `12.5 l/100 km` / `12,5 l/100 km`.
- `src/shared/i18n/useLanguageSync.test.tsx` — the stored preference is applied after hydration
  and followed live.
- UI: `SettingsScreen.test.tsx` (Romanian → the Theme label reads **Temă**; the picker switches
  live), `test/app/RootLayout.test.tsx` (Romanian tab titles), `ValueCard.test.tsx` (decimal comma).
- `src/features/ai-diagnose/agentStrings.test.ts` — every agent tool label (core, playbooks and
  every feature contribution), driver instruction and answer choice, end-of-run notice and core
  finding title / detail exists in English and Romanian.
- `jest.setup.ui.ts` puts every UI test back in English before it runs.

## Adding a language

1. Copy `src/shared/i18n/locales/en/` to `locales/<code>/` and translate every value (keep the keys
   and `{{placeholders}}`; give each plural key the categories `Intl.PluralRules('<code>')` reports).
2. Add the code to `SUPPORTED` in `src/shared/lib/i18nResolve.ts`.
3. Add the language's imports to `src/shared/i18n/locales/index.ts` (one per namespace).
4. Add the option to the Settings language picker (its name in its own language).
5. Point the parity test at the new language (`checkLocaleParity(resources.en, resources.<code>, 'en',
'<code>')`) — it then demands every key.

## Owner review

The Romanian strings were written without a native-speaker review. Before a release, the owner
reads through every `locales/ro/*.json`, paying particular attention to the **safety copy** of the
workshop screens: `routines.json` (interlocks, NRC explanations), `adaptations.json`,
`coding.json`, `serviceReset.json`, `settings.json` (reset all data, crash reports, security-access
plugins), `connection.json` (diagnosis suggestions) and the **AI diagnostic agent** copy:
`aiDiagnose.json` → `agent.*` (driver instructions and the stationary-car warning, end notices,
finding titles and details) and `share.*` (the Send to Claude / ChatGPT preview), plus each
feature's `agent.*` block (tool labels, feature findings). Corrections are edits to those files
only; the parity test keeps both languages in step.
