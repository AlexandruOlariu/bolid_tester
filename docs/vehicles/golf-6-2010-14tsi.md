# VW Golf 6 2010 — 1.4 TSI CAXA 90 kW / 122 cp (petrol)

A **Golf 6 (5K)**, VIN prefix `WVWZZZ1KZA…` (model-year letter `A` = 2010), built 2010-01. The
engine is a **1.4 TSI** turbocharged petrol, 90 kW; the engine code **CAXA** is confirmed by the
owner. The CAXA is **MAP-based (no MAF sensor)**.

This profile was **written from a vehicle-history report, not yet seen by the app**. Everything
below that the report cannot prove (protocol, PID list) is expected, not observed.

## Protocol

- **Expected:** `ISO_15765_4_CAN_11_500` (ELM327 protocol `6`), as on other VAG cars of this age.
- We still rely on **auto-detect** and record whatever the adapter negotiates; the profile's expected
  value is a hint and a sanity check.

## Live data we surface (`supportedPids`, 15)

Expected, unverified: the Punto petrol set without fuel level, plus the distance and barometric PIDs
the Golf Plus reports. Petrol exposes fuel trims and timing; the CAXA reports MAP rather than MAF:

`0104` load · `0105` coolant · `0106` short-term fuel trim B1 · `0107` long-term fuel trim B1 ·
`010B` MAP · `010C` RPM · `010D` speed · `010E` timing advance · `010F` intake air temp ·
`0111` throttle · `011F` run time · `0121` distance with MIL · `0131` distance since DTCs cleared ·
`0133` barometric · `0142` module voltage

> The real ECU's supported-PID **bitmap** is always authoritative at runtime; this list is what we
> expect and what the simulator emulates.

## On-car checklist (mirrored into `testChecklist`)

1. Connect with ignition on; confirm the negotiated protocol is **CAN 11/500**.
2. Read VIN (Mode 09) and confirm it matches the registration certificate.
3. Start the engine; read idle live data: RPM, coolant, MAP, fuel trims (near 0 %), timing
   advance, voltage (~14 V).
4. Compare the discovered PID list with the 15 expected; note every difference.
5. Read DTCs (Mode 03/07); note whether Mode 0A answers.
