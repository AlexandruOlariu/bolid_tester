# Google Play — Data safety answers

The answers for Play Console → **App content → Data safety**, derived from what the code does
(plan 30). Every row cites the code it comes from; when that code changes, change this sheet, the
[Apple sheet](./apple-privacy.md) and the [privacy policy](../../docs/privacy-policy.md) together
(the release checklist in [docs/release.md](../../docs/release.md#store-checklist) says so).
`storeConfig.test.ts` fails when a row cites no code path or a path that no longer exists.

**Play's definitions used here.** _Collected_ = sent off the phone by the app to the developer or
to anyone else. Data processed only on the phone is not collected. Data sent to a **service
provider** that processes it for the developer (Sentry for crash reports, Expo for updates) is
collected but **not shared**. Data the user sends on purpose with the share sheet, to an app they
pick, is neither.

## The AI assistant (not "collected" — explain it in the description and the policy)

**Diagnose (AI)** — each diagnosis, each step of the multi-step investigation (plan 34) and each
follow-up question — sends what the app has read for it to the AI provider **the user configured**:
fault codes and their descriptions, readiness monitors, the freeze frame, live values and short
recordings, make / model / engine, the VIN, the car's known checks for those codes and, when the
investigation reads them, control-module part numbers, software versions and fault codes,
manufacturer readings (extended data, adaptation and coding values, DPF values), recorded trip
values, fuel-economy and performance-test results, the maintenance log, past diagnoses and
fault-code checks from History, the user's alert rules, recent app error messages (VINs masked,
addresses removed), adapter details, the user's answers to the on-screen driver steps, the user's
question and the earlier answers. It goes to their own local server, or a cloud provider (OpenAI,
Anthropic, a custom URL) with **their own API key** (`src/shared/ai/openaiClient.ts`,
`src/shared/ai/anthropicClient.ts`, `src/shared/ai/http.ts`; the key in
`src/shared/state/secureApiKey.ts`). The developer runs no server and receives nothing; the
destination is chosen and paid for by the user, like a browser bookmark. That is why the form
answers **not collected** for it and the [privacy policy](../../docs/privacy-policy.md) describes it
in "When the app uses the internet".

**Send to Claude / ChatGPT** (on an AI report) is not a network call: it builds a plain-text summary
(the report, the fault codes and every check the investigation made), shows it first, and hands it
to the app the user picks in the share sheet, without the VIN unless the user turns on **Include
VIN** in that preview. Like the other exports it is not "collected" or "shared" by the developer.

> **Owner's judgement call.** If Play review disagrees (it treats a cloud preset as the app sending
> data to a third party), the conservative alternative is: _Other info → Other_ (vehicle
> diagnostic data) and _Personal info → Other info_ (the VIN): collected **and shared**, optional,
> App functionality, encrypted in transit "where the user's server supports it" — a local server
> may be plain HTTP on the LAN. Nothing in the code has to change for either answer.

### Permissions removed from the APK

Libraries merge in permissions the app never uses. `app.json` lists them under
`android.blockedPermissions`, so the release APK does not request them (check with
`aapt2 dump permissions`, [docs/release.md](../../docs/release.md)):

| Permission                                   | Merged in by                    | Why it is not needed                                                                                     |
| -------------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `SYSTEM_ALERT_WINDOW`                        | Expo / React Native template    | Only the development overlay draws over other apps; release builds have none.                            |
| `READ_EXTERNAL_STORAGE`                      | `expo-file-system`              | Files are written to the app's own folders and shared through the system share sheet or document picker. |
| `WRITE_EXTERNAL_STORAGE`                     | `expo-file-system`              | Same as above.                                                                                           |
| `USE_BIOMETRIC`                              | `expo-secure-store` (androidx)  | The API key is stored without `requireAuthentication` (`src/shared/state/secureApiKey.ts`).              |
| `USE_FINGERPRINT`                            | `expo-secure-store` (androidx)  | Same as above.                                                                                           |
| `com.google.android.c2dm.permission.RECEIVE` | `expo-notifications` (Firebase) | Notifications are local only; the app never requests a push token (`src/shared/notify/index.ts`).        |

`src/shared/lib/storeConfig.test.ts` fails if this list and `app.json` drift apart.

## Security practices section

- Encrypted in transit: **Yes** (above).
- Deletion request: **No** (above). If Play requires a deletion route anyway, point to the privacy
  policy's "Deleting your data" section.
- Data is not sold; no advertising SDK; no ads ID permission (`app.json` declares none).
